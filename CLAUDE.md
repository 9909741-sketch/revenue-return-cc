# Правила репозитория «Возврат выручки контакт-центра»

## Что это за проект
Инструмент для контакт-центра «Баусервис» (бренд Laparet): задачник по отменённым сделкам и тёплым лидам, возвращает выручку в продажу через повторный обзвон операторами КЦ.

## Стек
React + TypeScript (Vite, Tailwind CSS + shadcn/ui) на фронтенде, Node.js + Express + TypeScript на бэкенде, PostgreSQL (Replit Postgres) как хранилище.

## Команды
- Разработка: `npm run dev`
- Сборка: `npm run build`
- Запуск: `npm start`

## Где что лежит
- docs/ — проектные документы, источник истины (PASSPORT.md и SPEC.md главнее твоего мнения)
- src/ — исходный код интерфейса и сервера
- public/ — статические файлы
- deploy/ — архив для Replit

## Постоянные правила
1. docs/SPEC.md и docs/PASSPORT.md главнее твоего мнения. Расхождение решается в пользу документа.
2. Реальные ключи и пароли в репозиторий не попадают никогда. Только .env.example с пустыми значениями.
3. Каждое изменение фиксируется записью в docs/CHANGELOG.md.
4. Сущности и поля — только из docs/SPEC.md (блок «Модель данных»). Не выдумывай новых.
5. Коды статусов (NEW, WIP, NO_ANSWER, CANCEL_OK, CANCEL_BAD, REPASS, DONE_KC, WON, PASSED_TT, NO_RESULT) и коды причин (R01–R10, W01–W08) — используются дословно, не переименовываются.
6. Заглушки запрещены: объявленная функция работает.
7. Сервер слушает 0.0.0.0 и порт из переменной окружения PORT.
8. Стабильные ссылки строятся на устойчивом признаке (deal_id, email), не на сгенерированном идентификаторе.
9. Комментарии в коде — на русском, к каждому смысловому блоку.
10. Пустой перехват ошибок запрещён.
11. Проверка прав доступа выполняется на сервере до выполнения запроса, а не только скрытием элементов интерфейса.
12. Не выдумывать реальные ID полей/стадий Битрикс24 — использовать конфигурируемый маппинг «столбец выгрузки → поле модели данных».
