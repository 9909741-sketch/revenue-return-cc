# Возврат выручки контакт-центра (revenue-return-cc)

Внутренний инструмент контакт-центра компании «Баусервис» (бренд Laparet): два задачника на
общем ядре данных — отменённые сделки, переданные на торговые точки, и «зависшие» тёплые
лиды. Оператор КЦ звонит клиенту, фиксирует результат — статус и отчётность обновляются
автоматически.

Полное описание продукта — [docs/PASSPORT.md](docs/PASSPORT.md) и [docs/SPEC.md](docs/SPEC.md).

## Стек

- **Frontend**: React 19 + TypeScript, сборка Vite, UI на Tailwind CSS 4 (см. пояснение по
  UI-компонентам ниже).
- **Backend**: Node.js + Express 5, TypeScript, REST API.
- **База данных**: PostgreSQL (Replit Postgres в продакшене).
- **Менеджер пакетов**: npm (workspaces — `server/` и `client/` в одном репозитории).

## Быстрый старт

Подробная инструкция с пояснением каждой команды — [docs/RUN.md](docs/RUN.md). Коротко:

```bash
npm install
cp .env.example .env   # заполнить DATABASE_URL и SESSION_SECRET
npm run dev
```

Откройте http://localhost:5173 — в режиме разработки при первом запуске автоматически
создадутся демо-данные и тестовые учётные записи (см. docs/RUN.md). В production эти учётные
записи не создаются: задайте `INITIAL_ADMIN_EMAIL` и уникальный `INITIAL_ADMIN_PASSWORD`
длиной не менее 16 символов для создания первого администратора.

## Структура репозитория

```
server/   — Express API, доступ к PostgreSQL, бизнес-логика (см. server/src)
client/   — React-приложение (Vite)
docs/     — паспорт продукта, ТЗ, план, критерии приёмки, журнал решений
deploy/   — архив для загрузки в Replit (собирается на этапе 8)
```

## Важные технические решения

- Проект собирался автономно в среде без Node.js/npm/git — весь код написан вручную и не был
  скомпилирован и запущен агентом лично. Подробности и обоснование каждого решения —
  [docs/CHANGELOG.md](docs/CHANGELOG.md).
- UI-компоненты в `client/src/components/ui` написаны вручную в стиле shadcn/ui (Tailwind-классы),
  а не сгенерированы штатным CLI `npx shadcn add ...` — этот CLI требует npm, недоступного в
  среде сборки.
- Пакет `xlsx` (SheetJS) ставится не из обычного реестра npm, а с официального CDN проекта —
  так сейчас рекомендует сам SheetJS (реестр npm для этого пакета устарел и содержит
  уязвимости).
- Конфигурируемый маппинг «столбец выгрузки Битрикс24 → поле модели данных» — на экране
  «Импорт выгрузки», так как реальные названия колонок конкретного портала Б24 не были
  известны на момент сборки (см. RISKS.md, пункт 1).
