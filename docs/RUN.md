# Как запустить проект

Этот файл — пошаговая инструкция для человека без опыта администрирования серверов.
Каждая команда — со своей строки, с пояснением, что она делает и что должно появиться на экране.

Важно: сборка этого проекта выполнялась в среде без Node.js, npm и git (см.
[docs/CHANGELOG.md](CHANGELOG.md), запись «Этап 0. Ограничения окружения»). Ни одна из команд
ниже не была запущена агентом лично — они написаны по документации и по логике проекта, но
первый реальный прогон нужно сделать вам. Если что-то пойдёт не так на первом шаге — это,
скорее всего, несовпадение версий пакетов (см. раздел «Если что-то не работает» в конце файла).

## 0. Что должно быть установлено на компьютере

- **Node.js** версии 22 или новее (внутри уже есть npm). Скачать: https://nodejs.org — скачайте
  версию LTS. После установки проверьте в терминале:

  ```bash
  node --version
  npm --version
  ```

  Должны напечататься номера версий (например, `v22.x.x` и `10.x.x`). Если появилось
  «команда не найдена» — Node.js не установлен или не добавлен в PATH, переустановите.

- **PostgreSQL** версии 14 или новее — либо локально (https://www.postgresql.org/download/),
  либо через готовую базу (например, бесплатный PostgreSQL на Railway/Neon/Supabase для
  локальной проверки перед Replit). На самом Replit ничего ставить не нужно — там
  используется встроенный Replit Postgres (шаг 5).

- **Git** — только если хотите вести историю версий локально. Не обязателен для запуска
  приложения. Скачать: https://git-scm.com/downloads.

## 1. Установка зависимостей

Откройте терминал в папке проекта (`revenue-return-cc`) и выполните:

```bash
npm install
```

Что произойдёт: npm прочитает `package.json` в корне, `server/package.json` и
`client/package.json` (это npm workspaces — один репозиторий, два пакета) и скачает все
библиотеки в папки `node_modules`. Команда займёт от 30 секунд до нескольких минут. В конце
не должно быть красных строк с `npm error`.

После первого успешного `npm install` появятся файлы `package-lock.json` (в корне, в `server/`
и в `client/`) — их не было в архиве (см. docs/CHANGELOG.md), это нормально: зафиксируйте их
в git первым коммитом, чтобы дальше версии зависимостей были стабильны у всей команды.

Если увидите ошибку про пакет `xlsx` — это ожидаемо решённая особенность: он ставится не из
обычного реестра npm, а с официального CDN проекта SheetJS (см. запись в CHANGELOG «Выбор
версий пакетов») — адрес уже прописан в `server/package.json`, отдельных действий не нужно,
просто убедитесь, что есть доступ в интернет.

## 2. Настройка переменных окружения (только для локального запуска)

Скопируйте файл `.env.example` в `.env` в корне проекта:

```bash
cp .env.example .env
```

(В Windows PowerShell: `Copy-Item .env.example .env`)

Откройте `.env` и впишите значения:

- `DATABASE_URL` — строка подключения к вашей PostgreSQL, например
  `postgresql://postgres:пароль@localhost:5432/revenue_return_cc`.
- `SESSION_SECRET` — любая длинная случайная строка (например, 40 случайных символов).
- `ADMIN_RECOVERY_CODE` — необязательно для локальной проверки; если оставить пустым, аварийное
  восстановление администратора будет недоступно (это нормально для разработки).

Файл `.env` никогда не попадает в git (он в `.gitignore`) и не должен содержать реальные
боевые пароли — для локальной проверки подходит тестовая база.

## 3. Запуск в режиме разработки

```bash
npm run dev
```

Что произойдёт: одновременно запустятся сервер (Express, порт 3001 по умолчанию) и клиент
(Vite, порт 5173). При первом запуске сервер сам создаст таблицы в базе данных (миграция) и
демо-данные — в консоли появится сообщение «Демо-данные созданы» с адресами и паролем трёх
демо-пользователей.

Откройте в браузере: **http://localhost:5173**

Войдите одним из демо-пользователей (пароль для всех — `Demo12345!`, показан также в консоли
сервера при первом запуске):

- `admin@demo.laparet.local` — администратор (видит всё, управляет пользователями и импортом).
- `kc-head@demo.laparet.local` — руководитель КЦ (отчётность, все задачи).
- `operator@demo.laparet.local` — оператор КЦ (свои задачи в обоих задачниках).

**После первого входа рекомендуется сменить пароли демо-пользователей** через экран
«Пользователи» → «Сбросить пароль» (доступно администратору).

## 4. Сборка production-версии

```bash
npm run build
```

Что произойдёт: клиент соберётся в статические файлы `client/dist`, сервер скомпилируется из
TypeScript в JavaScript в `server/dist`. Ошибок компиляции быть не должно.

Для production задайте `NODE_ENV=production` и добавьте в переменные окружения:

- `INITIAL_ADMIN_EMAIL` — email первого администратора.
- `INITIAL_ADMIN_PASSWORD` — уникальный пароль длиной не менее 16 символов.
- `INITIAL_ADMIN_NAME` — имя администратора (необязательно).

Эти значения используются только если в базе ещё нет пользователей. После успешного первого
запуска удалите `INITIAL_ADMIN_EMAIL` и `INITIAL_ADMIN_PASSWORD` из переменных окружения или
Secrets. Без настроенных данных первого администратора пустая production-база не запустится.
В production демо-пользователи и демонстрационные сделки не создаются. При переходе со старой
версии приложение также удалит только встроенные демо-аккаунты, их сессии и тестовые записи.

```bash
NODE_ENV=production npm start
```

Запустит сервер (он же отдаёт собранный клиент как статику) на порту из переменной `PORT`
(по умолчанию 3001, если не задана). Откройте `http://localhost:3001`.

## 5. Загрузка в Replit

1. На https://replit.com создайте новый Repl → «Import from ZIP» (или «Upload folder») и
   загрузите архив `deploy/revenue-return-cc-replit.zip` из этого проекта.
2. В боковой панели Replit откройте вкладку **Database** → подключите **PostgreSQL**. Replit
   автоматически создаст переменную окружения `DATABASE_URL` — вписывать вручную не нужно.
3. Откройте вкладку **Secrets** (замок в боковой панели) и добавьте:
   - `SESSION_SECRET` — длинная случайная строка (сгенерируйте, например, командой
     `openssl rand -hex 32` в любом терминале, или любым генератором паролей).
    - `INITIAL_ADMIN_EMAIL` — email первого администратора.
    - `INITIAL_ADMIN_PASSWORD` — уникальный пароль длиной не менее 16 символов.
    - `INITIAL_ADMIN_NAME` — имя администратора (необязательно).
   - `ADMIN_RECOVERY_CODE` — секретный код для аварийного восстановления доступа
     администратора (см. docs/PASSPORT.md, блок 6). Если не задать — функция восстановления
     будет недоступна, приложение при этом всё равно запустится.
4. Нажмите **Run**. Replit выполнит `npm run build`, затем `npm start` (описано в `.replit`).
    При первом запуске создадутся таблицы и учётная запись администратора из указанных выше
    переменных. После этого удалите `INITIAL_ADMIN_EMAIL` и `INITIAL_ADMIN_PASSWORD` из Secrets.
    Демо-аккаунты с общим паролем в production не создаются.
5. Приложение откроется по адресу вида `https://<имя-репла>.replit.app`.

## Если что-то не работает

- **«Не задана обязательная переменная окружения DATABASE_URL/SESSION_SECRET»** — проверьте
  `.env` (локально) или Secrets (Replit). Без этих двух переменных сервер намеренно не
  запускается (так требует docs/PASSPORT.md, блок 8).
- **Ошибки TypeScript при `npm run build`** — этот код не был скомпилирован автором лично
  (см. docs/CHANGELOG.md), поэтому мелкие несоответствия версий пакетов возможны. Сообщение
  об ошибке компилятора обычно точно указывает файл и строку — большинство таких ошибок
  устраняется точечной правкой типов, без изменения логики.
- **Не приходит письмо/SMS клиенту** — это не функция этого MVP (оператор звонит вручную,
  инструмент только фиксирует результат, см. docs/PASSPORT.md, блок 2).
- **Заголовки столбцов в выгрузке не совпадают** — откройте экран «Импорт выгрузки» →
  «Маппинг столбцов» и впишите реальные заголовки вашего файла Битрикс24.
